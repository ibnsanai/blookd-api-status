3. Обязательные блокеры перед production-пилотом

Безопасность людей и денег

  1. createtransfers: route.js:2573-2594 принимает произвольные amount/account_id, config/payment.js:309-321 делает Stripe transfer без ownership. Отключить или ограничить и проверить тестом.
  2. PAN/CVV: сохранение CVV заменено на 0, но legacy приём включён по умолчанию (legacy-card-entry.guard.js:15). Подтвердить production flag и выполнить docs/security/pan-purge-plan.md; колонку удалить отдельным поздним contract-релизом.
  3. Пароли: Argon2id и lazy upgrade есть, но нужен явный PASSWORD_HASH_MIGRATION_ENABLED=true и план для оставшихся AES-записей.
  4. Auth bypass: auth.ts:9-21,38-42 пропускает проверку по любому совпавшему сегменту. Нужен exact method+template registry и deny-by-default tests.
  5. SQL: большая часть закрыта, но generic conditions/concatenation в config/common.js остаются. Закрыть все достижимые пути, не считать только количество исправлений.
  6. Секреты: APNs key из git history требует ротации; DOTENV_KEY больше не в image, но исторические секреты нужно отозвать.

Operational gates provider-share

  1. Назначить primary/backup owner.
  2. Применить sidecar migration на target; не применять contract.
  3. Настроить private network, service credential, DB least privilege, strict env.
  4. Записать local DTO/404, RPS, p95/p99, errors; настроить dashboard и реальные alerts.
  5. Проверить migration rollback/reapply и сохранить backup evidence.
  6. Подтвердить required branch protection администратором.
  7. Пройти local → shadow → remote cohort → local на target и записать mismatches=0, side effects=0 и время.
  8. Увеличивать cohort постепенно; 14 дней 100% remote до contract/local removal.

Hybrid readiness — detailed assessment

For project management · 25 November 2026 · dev@75beb25f. This is not a production approval.

Verdict: engineering preparation is approximately 80% complete; operational production readiness is approximately 60–65%. Only a controlled provider-share pilot is reasonable after the security and operational gates. Booking/Payments/Cancellation must not be split now.

Method and evidence

  • Compared the original audit, the 8 November snapshot, the 9 November strategy, and all subsequent security, DB, architecture, reliability, performance, runtime, CI, and extraction programs.
  • Inspected current production/auth/security code, migrations/models, shared writers, outbox/cron defaults, runtime, CI, and extraction behavior.
  • Reviewed 174 commits and 610 changed files since the closest snapshot commit b88b2c3a.
  • Loaded 294 v2/v3/web routes with zero errors. Counted 401 unit and 127 API spec files.

Percentages are expert readiness estimates, not code coverage. Production RPS/SLA, real data, live-v1 use, and alert delivery were not verified.

Mandatory security blockers before the pilot

  1. createtransfers: arbitrary amount/account_id reaches Stripe transfer without an ownership check. Disable or protect it and add regression coverage.
  2. PAN/CVV: stored CVV is forced to zero, but legacy acceptance is enabled by default. Confirm the production flag, execute the purge plan, and remove the column only in a later contract release.
  3. Passwords: enable staged Argon2id migration and define handling for remaining AES records.
  4. Authentication: replace path-segment bypass with exact method+template public routes and deny-by-default tests.
  5. SQL: close every reachable injection path; generic concatenated conditions remain in legacy helpers.
  6. Secrets: rotate the committed APNs key and other historical secrets. DOTENV_KEY is no longer baked into the image.

Mandatory operational gates for provider-share

  1. Assign primary/backup owners.
  2. Apply the sidecar migration, never the contract script, on the target.
  3. Configure private networking, service credentials, least-privilege DB access, and strict environment validation.
  4. Record local DTO/404, RPS, p95/p99, and errors; configure and test dashboards and alert routes.
  5. Prove migration rollback/reapply and retain backup evidence.
  6. Have an administrator confirm required branch protection.
  7. Complete target local → shadow → remote cohort → local with zero mismatches and external effects.
  8. Expand gradually and complete 14 days at 100% remote before contract cleanup or local-path removal.

Blockers for subsequent stages

  • Reporting: report parity, read-only DB user, resource baseline, effect sandbox, and rollback.
  • Notifications: all producers in same-transaction outbox, one writer, provider idempotency/reconciliation, staged cron locks, real process-kill rehearsal, DLQ/alerts.
  • Web BFF: exact public routes, Identity anti-corruption API, one account/session writer, token compatibility, and nginx group rollback.
  • Core: no extraction until data ownership is independent, cross-domain SQL/transactions are removed, and saga/reconciliation and failure drills exist.
