2. Таблицы на удаление

Подтверждённых кандидатов на удаление нет. Все 42 имени встречаются в статически достижимых route flows или связанном ownership flow. Отсутствие чтения таблицы конкретным endpoint не доказывает отсутствие записи/внешнего consumer.
  • rent_reporting_workspace_daily — не найден SQL чтения/записи reporting aggregate; имя присутствует в schema и ownership migration. Недостаточно данных о внешних jobs/BI. Не удалять без runtime inventory.
  • rent_booking_events_outbox — заполняется booking routes, поэтому не является неиспользуемой; отсутствие consumer вынесено в проблемы кода.
  • Для безопасного retirement нужны production query log, список cron/Lambda/BI и период наблюдения. Сейчас: Недостаточно данных.

5. Приоритизированный план действий

P0 — немедленно, до следующего production rollout

  1. Исправить history query под фактический DDL и добавить MySQL regression для cancel-request deny.
  2. Запретить reschedule после failed payment unwind; сохранять финансовую историю и идемпотентно повторять saga.
  3. Добавить atomic charge claim и reconciliation; устранить concurrent capture.

  1. Сделать backup + duplicate/orphan report; добавить provider_ref, social identity, export queue и booking date-range indexes после EXPLAIN.
